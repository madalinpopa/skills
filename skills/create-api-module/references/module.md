# Module anatomy

A module is a feature slice that owns its HTTP contract, its Postgres schema,
its migrations, and its tests. Other modules reach it only through the
contracts registry. The script writes this tree for module `brand` with
entity `profile`:

```
api/internal/modules/brand/
├── module.go                  Module implementation; embeds the migrations
├── config.go                  Config with Validate; one field per setting
├── domain/
│   ├── profile.go             Profile entity, ProfileUUID, constructor
│   ├── errors.go              ErrNotFound, ErrEmptyName
│   └── repository.go          ProfileRepository interface
├── app/
│   ├── command.go             Command with CreateProfile
│   └── query.go               Query with GetProfile
├── adapters/
│   ├── rest/
│   │   ├── openapi.yaml       POST /brand/profiles, GET /brand/profiles/{uuid}
│   │   ├── oapi-codegen.yaml  echo5-server, strict-server, models
│   │   ├── handler.go         Handler, NewHandler, Register, go:generate
│   │   ├── profile.go         handler methods implementing StrictServerInterface
│   │   ├── server/            generated: server.gen.go
│   │   └── client/            client.go, oapi-codegen.yaml, generated client.gen.go
│   └── pgstore/
│       ├── sqlc.yaml          pgx/v5, typed UUID override
│       ├── sqlc.go            go:generate go tool sqlc generate
│       ├── migrations/        0001_init_profiles.up.sql
│       ├── queries/           profiles.sql
│       ├── models/            generated by sqlc
│       └── profile_repo.go    ProfileRepository backed by the generated queries
└── tests/
    ├── setup_test.go          TestMain: container, wire the module, serve
    └── profile_test.go        create then get, and a 404
```

## Lifecycle

`module.go` implements the `modules.Module` interface from the layout:

- `Name` returns the module name. It is also the Postgres schema name.
- `Init` validates the config, builds the repository, the command and query
  handlers, and the REST handler, then runs the embedded migrations through
  `pgkit.MigrateDatabaseUp`.
- `RegisterContracts` and `Connect` are empty until the module publishes a
  contract or depends on one. See below.
- `RegisterHTTP` registers the generated routes on the router.

## Registration

The script makes two edits outside the module and `go build` proves them:

- `internal/server/server.go`: one line in the `allModules` slice,
  `brand.NewModule(c.BrandConfig, pool)`, plus the import.
- `internal/server/config.go`: one field, `BrandConfig brand.Config`, plus the
  import. `LoadConfigFromEnv` grows a loader for it when the config gets
  settings.

## Dependency rules

- `domain` imports only the standard library. Identifiers are named types
  over `uuid.UUID` from the Go standard library, so pgx and sqlc handle them
  without a wrapper.
- `app` imports `domain` and defines the ports it needs. The starter uses the
  repository interface from `domain` as its only port and takes a clock.
- `adapters/rest` imports `app` and `domain`. Handlers map domain errors to
  the typed error responses declared in the spec, so no error package is
  needed yet.
- `adapters/pgstore` imports `domain` and its generated `models`. It maps
  `pgx.ErrNoRows` to `domain.ErrNotFound`.
- `module.go` is the only file that imports every layer.
- The module never imports another module.

## Generated code

`task gen` from the project root, or `go generate ./internal/modules/brand/...`
from `api/`, regenerates:

- `adapters/rest/server/server.gen.go` and `adapters/rest/client/client.gen.go`
  from `openapi.yaml`. Handlers implement `server.StrictServerInterface`.
  Tests use the client.
- `adapters/pgstore/models/` from `migrations/*.sql` as schema and
  `queries/*.sql` as queries. sqlc needs at least one query.

Never edit generated files. Change the spec or the SQL and regenerate.

## Tests

`tests/setup_test.go` runs only with `INTEGRATION=true`. `TestMain` starts a
Postgres container through `testkit.Start`, wires the module with `env.Wire`,
which runs the same five phases as `server.New`, and serves it with
`env.Serve`. Tests call the generated client against `env.URL`.

Unit tests for `domain` and `app` need no container. Add them beside the code
when the entity gains rules worth testing.

## Publishing a contract

When another module needs something from this one:

1. Add an interface and a field to `internal/modules/contracts.go`, and a nil
   check in `Verify`.
2. Add `contract.go` to the module with a type implementing the interface.
3. Set the field in `RegisterContracts`.

A module that depends on a contract reads it in `Connect`, never in `Init`,
because the registry is complete only after every module has published.
